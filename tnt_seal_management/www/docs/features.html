Introduction & Setup

Get acquainted with the core architecture of the TNT (Track & Trace) Seal Management system and set up the foundation data required for daily operations.

What is TNT Seal Management?

TNT Seal Management is a cargo security and transit tracking platform. It integrates electronic hardware seals (e-seals) with custom workflows to monitor transit routes, detect geofence violations, trigger immediate tampering alerts, and manage client invoicing.

System Workspaces & Navigation

All management tasks are performed inside the Frappe Desk. Users with designated roles (System Manager, Operations Control Room, Field Technician, Customer Care) can access the system.

  • Global Search (Ctrl + G): Use this shortcut to quickly find doctypes like Vehicle, Seal Device, or Custody Point.
  • Sidebar Modules: Jump directly to the custom dashboard modules like Control Room or Billing Manage.

Master Data Setup Checklist

Before configuring seals or dispatching journeys, ensure you have set up the following foundation records:

1. Custody Points (Warehouses)

Define physical storage hubs, custom warehouses, or regional branches where seals are stored when not in transit.

  • Is Main Warehouse: Flag this to denote final drop-off points for untagged returned devices.
  • Geofence Radius (m): Set a matching radius (default: 300m) to automatically trigger custodian updates when seals enter geographical limits.
2. Vehicles

Register all transit trucks or fleet assets that carry cargo requiring seal tracking.

  • Naming Expression: Naming follows the automated format VEH-YYYY-MM-#####.
  • Vehicle Status: Mark as Active, Maintenance, or Inactive depending on fleet availability.
3. Transport Locations

Log key transit checkpoints along routes, ports, border posts, and custom depots. You can define checkpoints at /app/transport-location by searching for transport-location in the global search.

  • Location Types: Support for Ports, Inland Container Depots, Border Posts, Weighbridges, and Cities/Towns.
  • Country Limits: Map locations across standard East African jurisdictions (Kenya, Uganda, Tanzania, Rwanda, Burundi, DR Congo).
4. Seal Devices

Establish tracking units by entering physical seal serial keys and registering hardware IDs.

  • Hardware Mapping: Associate e-seals with unique Device ID and IMEI Number parameters for GPS API telemetry sync.
  • Status Tracking: Displays real-time device health: battery levels, lock status (Locked/Unlocked), and current custodian status.

Customer Bookings

Manage incoming seal tagging requests, verify financial clearances, and initiate the trip dispatching workflow.

The Booking Lifecycle

Every seal tracking journey starts with a Customer Booking request. The diagram/flow below highlights the key transition milestones:

1. Request Submitted via Portal or Account Manager
2. Review Pending Account Manager & Finance Review
3. Job Order Approved and PCB Job Order is generated
4. Journey Request Matched to Vehicle, Driver, & Route

1. Submitting a Booking Request

Tagging requests can enter the system via two distinct sources:

  • Customer Web Portal: External clients log in directly and submit requests specifying the location, date/time, and on-site contact details. These bookings carry the Customer Portal source flag and are set to Draft.
  • Account Managers: Internal account reps can log a booking manually on behalf of a customer in the Desk, entering client associations and scheduling details.

2. Verification & Financial Approval

To prevent unauthorized dispatches, bookings require authorization before field technicians are mobilized:

  • Account Manager Review: The booking is reviewed internally to ensure details match the client contract.
  • Finance PCB Approval: Users with the Finance PCB role review the billing rates and approve the request. Once confirmed, the booking status transitions to Finance PCB Approved.
Permission Restrictions

Only users with the Finance PCB role can update the approval sections. Standard users, account managers, and field technicians can view but not edit approval statuses or remarks.

3. Generating the PCB Job Order

Upon financial approval, a PCB Job Order (JO-YYYY-MM-#####) is automatically created and linked to the booking record. The Job Order manages field assignments and scheduled times, mapping the scheduled date, location, and site contact details from the original booking.

4. Journey Request Setup

The final step in the booking workflow is matching the Job Order to a physical vehicle and trip route to build the Journey Request:

  • Vehicle & Container Association: Link the specific tracking vehicle and enter the cargo container number (required).
  • Route Definition: Set the trip Origin and final Destination, and list any mandatory intermediate transit Checkpoints.
  • Driver Contact: Capture the active driver's phone number to maintain communication during tracking.
  • Seals Required: Input the quantity of electronic locks (seals) to be attached for this tracking journey.

Inventory & Devices

Procure seals, manage regional stock transfers, and oversee physical hardware lifecycles.

1. Seal Devices Registry

Every tracking unit in the system is managed inside the Seal Device doctype. This directory logs the hardware attributes and live telematics:

  • Unique Identity: Managed via a primary `Device ID` and mapped to its cellular/telemetry `IMEI Number` (mandatory field).
  • State Management: Shows the lock/unlock states of physical latches and tracks real-time battery voltage percentages.
  • Custody Status: Keeps track of the device's physical custodian (e.g., whether it is held by an individual Field Technician, assigned to an active transit vehicle, or stored in a specific Custody Point).

2. Ingesting New Inventory (Seal Acquisitions)

New hardware batches bought from vendors are registered using the **Seal Acquisition** (SA-YYYY-MM-#####) document:

  • Receipt Details: Form requests require documenting the Supplier link, Invoice/PO reference, Received Date, and receiving target Custody Point warehouse.
  • Batch Ingestion: Seal records are linked in the `Seals Received` child table where serials, device IDs, and IMEIs are entered.
  • Ingestion Statuses:
    • Draft: Pending review. Sealing devices are inactive in backend lookups.
    • Quality Check: Batch requires quality review. Devices cannot be dispatched to field agents.
    • Received / Available: Stock is committed. Seal records are activated and marked as Available at the target Custody Point.

3. Internal Stock Transfers

To move device stock between regional warehouses (e.g., from the main container port depot to an inland border custody point), users use the **Seal Stock Transfer** (SST-YYYY-MM-#####) doctype:

  • Initiating Transfers: Select the Source Warehouse and Target Warehouse, and insert the specific devices into the `Seals` child table. When submitted, the transfer state updates to In Transit, and the seals are locked from active field dispatches.
  • Completing Transfers: Upon physical arrival at the destination warehouse, the receiving officer clicks the Receive action. The document status updates to Received, logging the Received Date and custodian changes, and releasing the devices to Available status at the target Custody Point.

Field Operations (PCB)

Coordinate the physical lifecycle of e-seals in the field, allocate technician resources, and verify pre-tagging inspection parameters.

1. Technician Assignments & Dispatch

Once a PCB Job Order is generated, it must be assigned to an active field technician. This is managed by the PCB Team Leader using the PCB Assignment (ASG-YYYY-MM-#####) doctype:

  • Request Types: Assignments are categorized by operation type:
    • Tagging: Physical installation and lock-activation of seals at the origin point.
    • Untagging: Safe unlocking and physical removal of seals at the trip destination.
    • Seal Return: Handing back the recovered physical seal to a main regional warehouse.
  • Assignment Status: Monitored from Pending to Assigned, ensuring each step of the journey's physical handling is allocated to a technician.

2. Execution: Pre-Tagging Inspection Checklists

To ensure telemetry hardware integrity and minimize transit tracking errors, field technicians must run inspections using the **Pre-Tagging Checklist** table before activating a tracking journey:

Standard Pre-Tagging Checks
Device Battery: Confirm battery level is above 80% charge.
Sim Card status: Verify cellular network sync and GSM transmission state.
Physical Condition: Inspect device housing and lock cable for mechanical damage.
Mounting Points: Check container or truck handle points for secure lock attachment.

All checklist lines are populated from pre-tagging templates and must be flagged as Completed in the Journey Request child table before the tagging transaction is submitted.

3. Completing Physical Tagging

During the physical attachment process, the field technician must perform the following inputs:

  • Document Uploads: Upload copies of customs declarations or shipping manifests to the Entry Pictures table, and attach high-resolution photo proof of the installed, locked seal under Tagging Pictures.
  • Actual Tagging Timestamp: Log the exact date and time the seal was secured.
  • GPS Coordinates Lock: Once the seal is locked, check off the Tagging Completed checkbox. The system will automatically query the seal device's GPS and pull the current coordinates into the Tagging Location field to serve as the geofence origin point.

Control Room & Tracking

Monitor active transport journeys, track real-time telemetry, and respond to security exceptions.

1. Live Journey Tracking (Seal Journey)

Once a vehicle departs, its transit state is managed within the Seal Journey (SJ-YYYY-MM-#####) record. Operators can track real-time telematics from the Transit / API Tracking tab:

  • Device Telemetry: Features real-time values including API Device Status, API Battery Level, API Speed, and the last update timestamp.
  • Location Coordinates: Captures live API Latitude and API Longitude coordinates, automatically updating the current geofence mapping.
  • Connection Health: Connection drops or synchronization errors will log in the API Sync Error field, alerting operators to connectivity problems.

2. Alarm & Exception Management (Seal Alert Log)

Security incidents or hardware problems trigger entries in the Seal Alert Log (SAL-YYYY-MM-#####) registry. Alerts come from two distinct streams:

  • System Alerts: Internally triggered rules monitoring device timeouts (connectivity lost) or low battery levels (battery below 15%).
  • Uffizio Alerts: Live alerts pushed directly from external Uffizio telemetry feeds (e.g. casing tampering, cable-cut alarms, geofence deviations).
Alert Resolution Protocol

When a critical or warning alert triggers, operators must execute the following clearing checklist:

  • Acknowledge Alert: Toggle the Acknowledged checkbox, which automatically registers your username under Acknowledged By and stamps the current time.
  • Investigate & Resolve: Review the raw JSON payload in the Raw Data field, contact the driver/transporter if required, and log your resolution findings in Acknowledgement Remarks.
  • Close Status: Advance the Resolution Status from Open → Underway → Resolved.

3. Journey Completion & Untagging

When a vehicle arrives at its destination transport location, the final untagging checklist and return sequence are initiated:

  • Unlocking Method:
    • Physical: The Field Technician physically unlocks the seal at the border/port, logging the untagging start and completion timestamps.
    • Remote: Operators trigger a remote lock-release from the control room console, skipping the manual untagging steps and moving directly to custody return.
  • Operator Sign-Off: Operators review arrival remarks, check off the Untagging Confirmation and Seal Unlocked Confirmation toggles (exclusive permissions), and advance the status to Awaiting Seal Return.

Billing & Finance

Establish customer pricing rules, manage subscription contracts, and calculate journey-based lease expenses.

1. Setting up Subscription Rates (Seal Billing Rate)

Electronic lock rentals are configured under the Seal Billing Rate doctype. This directory defines standard subscription terms:

  • Billing Periods: Supports Weekly, Monthly, Quarterly, Semi-Annually, Annually, Date Range, and Custom Days.
  • Pricing Parameters:
    • First Period Days: The initial days included in the subscription baseline (default: 5 days).
    • First Period Amount: The cost charged for the baseline period (default: 1000 KES).
    • Extra Day Rate: The daily penalty fee charged for every day exceeding the baseline period (default: 500 KES).
  • Global Default: Marking a rule as the global default sets it as the system-wide fallback pricing rule.
Executive Approval Required

New subscription rules or changes to existing approved rates require sign-off from the Managing Director. The rule is set to Pending Approval upon creation and cannot be assigned to clients until its status advances to Approved.

2. Mapping Customers (Customer Billing Assignment)

Assign billing rules to specific clients or customer categories using the Customer Billing Assignment (CBA-#####) doctype:

  • Scope Mapping: Apply assignments to an individual Customer or an entire Customer Group.
  • Priority Weighting: Higher priority values override other matching rules when multiple assignments apply to the same client.
  • Outright Purchase Option: For clients who own their physical seal hardware, toggle the Outright Purchase checkbox and record the Number of Seals Owned. This flags the backend to skip lease charges for those units.
  • Contract Overrides: Define custom pricing without modifying shared billing rates using the Rate Override and Currency Override fields (exclusive to that client's assignment).
  • Extra Billing: For secondary leasing arrangements that run parallel to a customer's primary subscription, toggle the Extra Billing Agreement checkbox.

3. Cost Calculations on Journey Completion

When a journey transitions to Completed, the backend automatically calculates the rental fees in the Billing tab:

Billing Calculation Breakdown Formula:

Total Charge = (First Period Amount + (Extra Days * Extra Day Rate)) * Seal Count
  • Billable Days: The duration between billing start (tagging) and billing return (seal received at warehouse).
  • Extra Days: Billable days exceeding the First Period Days parameter.
